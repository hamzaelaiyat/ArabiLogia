## 0. Project context

- **App:** Flutter web app for Arabic-speaking students (Arabic-only UI, RTL everywhere). Deployed to Vercel at `https://arabilogia.vercel.app`.
- **Repo root:** `/mnt/Storage/projects/ArabiLogia`.
- **Build & deploy:** `flutter build web --release` → `rm -rf web/* && cp -r build/web/. web/` → `npx vercel --yes --prod --force`.
- **Critical build quirk:** `flutter build web` writes fresh dart2js output to `.dart_tool/flutter_build/<hash>/main.dart.js` but the final `build/web/main.dart.js` copy can stay **byte-identical to the previous build** in this environment. After every build, `md5sum build/web/main.dart.js` and `grep` for a fresh marker. If stale, `cp .dart_tool/flutter_build/*/main.dart.js build/web/main.dart.js` and re-verify.
- **Verification on Vercel:** `curl -sI https://arabilogia.vercel.app/main.dart.js | grep -iE 'etag|last-modified'` then `curl -s https://arabilogia.vercel.app/main.dart.js | grep -c '<fresh-marker>'`.
- **Local headless test:** `setsid python3 /tmp/opencode/spa_server.py >/tmp/opencode/spa.log 2>&1 < /dev/null & disown` then `/usr/bin/google-chrome-stable --headless=new --disable-gpu --no-sandbox --enable-logging=stderr --v=0 --virtual-time-budget=30000 --user-data-dir=/tmp/opencode/chrome_<tag> http://127.0.0.1:8899/<route>`.
- **Private feature rule (still in force):** `lib/features/gate/`, `supabase/`, `scripts/` and any gate-related lines in `lib/core/routes/app_router.dart` must never be committed to public. AGENTS.md rules: no code comments unless asked; preserve existing conventions.
- **Tests must stay green:** `flutter test` currently reports **46 passing tests** across existing suites.
- **Lint:** `flutter analyze` currently clean (only pre-existing info-level lints).

- `lecture_card.dart` is a 40px icon + 1-line title + 1-line description. No thumbnail, no duration, no progress bar.
- `lectures_screen.dart` has tab-per-subject, ListSkeleton, retry button — but no search, no sort, no grid on desktop, no thumbnail grid.
- `_loadLectureDetails` blocks on every exam load sequentially — consider `Future.wait` if list grows.

## 4. Risks & mitigations

- **`youtube_player_iframe` on web**: needs YouTube IFrame API. May be blocked in corporate networks. Mitigate by lazy-mounting and falling back to a "open externally" button if the iframe fails to load.
- **Lazy YouTube mount**: use `Visibility(maintainState: true)` or a `ScrollController` listener that mounts the iframe only when within 200px of the viewport.
- **Confetti perf**: cap particle count, use `BlastDirectionality.explosive` with a low count (~30 particles).
- **Autosave conflict**: `SharedPreferences` write is async; debounce writes with a `Timer` (cancel + reset on every change) instead of interval-based.
- **Background time correctness**: multi-pause requires `List<DateTime>` stack — make sure to `pop` on resume, not just overwrite.
- **Result view unification** is a refactor — keep the existing `exam_result_screen.dart` and `practice_result_screen.dart` public constructors unchanged so route params don't break.
